00 / DESIGN POSITION

当工具本身也要被观看，它如何在作品与设备之间保持张力？

Range Echo 是一件由实时声音驱动的浏览器视觉作品，也是一套可以接入麦克风、音频文件、MIDI 与 OSC 的现场控制工具。它的设计命题不是怎样把更多参数放进屏幕，而是怎样建立正确的观看顺序。

ARTWORK FIRST. CONTROL ON DEMAND.
01

INTERFACE AS STAGE

界面不是画框，而是舞台

传统控制台习惯把控件放在第一层，把视觉结果留在一个被切割的小窗口里。Range Echo 反转了这个关系：全屏粒子场是舞台，控制系统退到右侧抽屉中。第一次打开页面，观众先感受到尺度、黑场与运动；需要操作时，界面才显露出设备属性。

画面中心被完整留给声音事件。标题位于左上，控制入口位于右上，模式选择贴近左侧，实时读数沉到底部。所有固定信息都绕开中心，因为中间必须容纳最强的中低频力量、白热冲击以及向外扩张的波纹。

巨大的 RANGE ECHO 不是品牌装饰，而是稳定的视觉锚点。粒子不断流动、扩散、旋转，粗重而静止的字体为画面提供重量，让页面更像一张持续变化的音乐海报，而不是普通的 WebGL Demo。

02

THREE VISUAL LANGUAGES

A / EDITORIAL BRUTALISM

坚硬的排版

大字号、硬边框、高对比和编号负责建立结构。界面刻意避开圆润卡片与“未来玻璃”，因为粒子画面已经足够柔软。坚硬的排版让它不至于滑向模板化的 Web3 审美。

B / AUDIO SPATIAL NARRATIVE

声音制造事件

中低频从中央扩散，重低音留下不可见落点的冲击反馈，高频以流星快速穿过空间。差异不靠彩虹分色，而由运动、尺度、方向和寿命表达。

C / LIVE AV LOGIC

可信的设备感

等宽字体、状态灯、参数分区与 A–H 场景记忆构成专业 rack 的语法。关闭抽屉，它是一件作品；打开抽屉，它是一台可以工作的设备。

03

FROM FFT TO EVENT

频率不是数据列，而是空间角色

  • LOW–MID中央聚集力量，产生向外移动并衰减的波前。
  • SUB–BASS触发源保持不可见，只呈现落点、凹陷与反向冲击。
  • HIGH成为短促的流星与碎光，不持续占据画面。
  • BPM提供旋转与呼吸基准，但不让所有动画机械卡拍。
  • IDLE没有输入时仍保持轻微呼吸，避免退化成待机页。
04

COLOR & MATERIAL

黑、洋红与白热

黑色不是空白背景，而是距离。紫色和洋红承担持续能量：比纯蓝更有体温，又比红色更适合长时间观看。白色只出现在最强的波前和冲击边缘，成为短暂的“过曝”。

颜色维持统一情绪；声音差异交给运动表达。白色因此代表真正的峰值，而不是普通照明。

05

PERFORMANCE AS AESTHETIC

限制形成纪律

项目把 Apple M1、16GB 内存作为明确上限。默认由 25,600 个核心点与 8,000 个氛围粒子组成，高画质也不超过 49,600 点。

单一 GPU Shader、点精灵光核、有限后期和共享粒子池，共同构成一种轻量但不轻薄的网页视觉。

06

REFERENCE, NOT REPLICA

参考，而不是复刻

项目从 Particleify 的全屏粒子构图中学习尺度、景深与“设置服从画面”的关系；从《音域回响》式音乐壁纸中学习低频的中心性、波纹扩散和突发事件；再把这些经验放入现场 AV rack 的交互框架中。

它们被重新组织为一个属于浏览器的命题：如何让一个可以独立打开的网页，同时具有音乐壁纸的沉浸感、生成艺术的可塑性，以及现场工具的可信度。

DESIGN CONCLUSION

远看，是一张持续变化的音乐海报。
近看，是一套可以真正接入声音的视觉系统。

这套 UI 的价值不在于装饰了多少功能，而在于建立了清楚的观看顺序： 先进入声音的空间，再决定是否触碰控制。
